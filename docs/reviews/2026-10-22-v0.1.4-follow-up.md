# v0.1.4 桌面复审

日期：2026-10-22。基线：已发布的 v0.1.4，提交 639e65a。
范围：升级数据、并发写入、导入回滚、AI 请求链路。使用合成数据及临时 SQLite 文件，未读取或修改正式用户数据库。

## 确认问题及修复

### P2：同一窗口连续保存设置会覆盖前一次修改

位置：`src/features/preferences/preferenceStore.ts`。

两个保存操作都在等待数据库之前读取同一份旧状态。并发修改主题与 AI 角色后，角色保存成功，但主题从 dark 退回 light。新增测试在 v0.1.4 上复现。

修复：复用写入队列，在前一个操作完成后再计算下一份设置。写入失败不会阻塞后续保存。覆盖并发保存及失败后恢复测试。

该队列仅保证当前 JavaScript 运行实例的顺序；偏好存储仍没有跨窗口的条件更新。多实例同时编辑设置不是本次已验证的保证范围。

### P2：根地址返回 JSON 404 时，AI 地址回退失效

位置：`src/lib/ai/llmClient.ts`。

服务配置为根地址、实际聊天接口位于 `/v1/chat/completions` 时，报告请求在第一个地址返回 JSON 404 后直接退出；测试连接没有使用报告生成的候选地址流程。两个入口均通过桌面 IPC 模拟测试复现。

修复：测试连接与报告请求复用同一处理函数。404/405 或成功状态的非 JSON 页面允许尝试下一个候选路径；401 等鉴权失败直接返回，保留 HTTP 状态。覆盖两个入口的 JSON 404 回退及 401 不重试。

### P2：工作区初始化失败后没有恢复入口

位置：`src/lib/storage/sqliteStorageAdapter.ts`、`src/app/useAppBootstrap.ts`。

SQLite 首次加载被拒绝后，缓存保留失败 Promise，后续加载持续失败。启动钩子的异步错误也未进入页面错误边界，界面可能停留在加载状态。

修复：失败时清除数据库连接 Promise 缓存；启动错误进入现有错误边界，显示重新加载入口。已覆盖首次失败后再次打开，以及加载失败时的页面恢复入口。

## 其余核验结果

- 升级：对比 v0.1.3 的提交 f0dd52e 与 v0.1.4，迁移函数及 SQL 内容完全一致，正式应用标识未变。本次没有引入新迁移。此结论来自代码对比，不等同于真实用户数据库升级验收。
- 导入：新增磁盘 SQLite 测试，在全部原表删除后、最后的 preferences 写入阶段注入失败；关闭并重新打开数据库，projects、tasks、focus_refs、reports、preferences 五表原始内容全部保留。
- 并发：新增 WAL 模式、四连接池测试，两个连接按同一旧状态同时更新项目，只有一个成功；另一方读取最新值后可以成功重试。原有任务并发、焦点冲突和删除项目级联测试继续通过。
- AI：保留原生 HTTP 本地服务器测试、请求发出前取消和请求进行中取消测试。真实供应商鉴权、真实网络超时及代理环境未做新的端到端联调。
