## Scope

Reviewed the local changes since v0.1.3, plus related Today priority controls,
checklist writes, AI settings requests, and snapshot export. This is a targeted
review, not a full security audit of every module.

## Findings Addressed

- P2: Today priority menus were clipped by both title ancestors. Removed those
  clipping boundaries while keeping title text truncation. The menu stays over
  the checklist without changing card height. Outside pointer actions and Escape
  close it; Escape restores focus to the trigger. Menu surfaces follow the theme.
- P2: Fixed card grid rows exceeded the available inner height. Adjusted their
  budget so three checklist lines and the footer fit a 260px card.
- P1: Parallel edits of one task overwrote each other. Reproduced two concurrent
  checklist toggles leaving only one item completed. Serialized task mutations by
  task ID, including deletion and restoration. Failed saves do not block later
  edits. This queue applies to one store instance, not multiple app processes.
- P2: Switching or editing AI profiles during a request could display results
  from the old configuration. Invalidated outstanding results on configuration
  changes, profile creation/cancellation/deletion, and unmount.
- P2: HTTP 200 HTML responses and empty completions were reported as successful
  API tests. Parsing failures and missing completion content now produce errors.
- P2: Top-level model arrays were ignored. Added support without changing the
  existing OpenAI data-array and provider models-array formats.
- P2: Desktop builds used WebView HTTP while development used a Vite proxy.
  Desktop AI requests now use the native Rust command in both modes. The target
  service rejected an unauthenticated browser preflight with 403, while an
  unauthenticated GET returned 401. No real API key was used for these probes.

## Open Finding

- P2: Default snapshots include plain API credentials. `exportSnapshot.ts:34`
  returns the full preferences object, including `aiKey` and each profile's
  `apiKey`. The development snapshot sync also writes this export to a local
  JSON file. Sharing a backup therefore shares the credentials. Consider a
  credential-free export by default, an explicit option for full credential
  backups, and OS Keychain storage for the installed app. No backup format or
  key-storage migration was introduced in this patch.
